# LRWeb website: notes for Claude

This folder is the redesigned website for **LRWeb** (lrweb.uk), a two-person UK web studio run by **Luke Harris-Platt** (Wokingham) and **Ralph Ogilvy** (Hungerford & Kintbury, Berkshire). LRWeb builds websites for small businesses and then hosts and looks after them on monthly care plans. Luke is the person you'll usually be talking to. He isn't a developer, so explain changes in plain English, show him the result, and don't make him read code.

Alongside the LRWeb pages are seven **example client sites** in `work/`, used as a portfolio.

## House rules (always follow these)

- **Never use em dashes** (the long dash) anywhere: copy, code comments, commit messages. Use a comma, colon, full stop or brackets instead. `npm run check` catches them.
- **Never say or imply the sites are hand-coded or hand-written.** Don't add wording like "hand-built", "handcrafted code" or "written line by line".
- **Plain English.** Readers include older, non-technical business owners. Explain jargon or avoid it. There's a tooltip helper for unavoidable terms (see "Jargon tips" below).
- **Don't invent facts about LRWeb.** Company details, prices, policies and promises come from Luke or the existing pages. If a change would add a new promise (a response time, a number, a schedule), check with Luke first. He keeps a private checklist of every promise the site makes; ask him for it rather than guessing. Don't copy that checklist into this repo: the repo may be public.
- **Keep the motion, but make it safe.** Animations are a big part of the brand. Every effect must still work with `prefers-reduced-motion: reduce` (content visible, nothing stuck hidden) and must not block scrolling.
- **Phones are first-class.** Check every change at 360px and 412px wide as well as desktop. Many visitors are on phones.

## How the site is put together

Plain static HTML/CSS/JS. No framework, no bundler.

| What | Where | How to edit |
|---|---|---|
| LRWeb pages: `index`, `services`, `pricing`, `about`, `work`, `referrals`, `contact`, `privacy`, `terms`, `404` | generated by `_src/build.py` | **Edit `_src/build.py`, then run it.** Never edit these `.html` files directly: the next build overwrites them. |
| Shared styles | `assets/css/site.css` | Edit directly. Later rules are grouped in dated blocks (`v3`, `v4`, `v5`, `v6`) and win over earlier ones. |
| Behaviour (animations, estimator, forms, tooltips) | `assets/js/site.js` | Edit directly. |
| WebGL night sky and sunrise | `assets/js/sky.js` | Edit directly. Used via `<canvas class="sky-gl" data-prog data-hz data-sunx data-sunr data-aurora>`. |
| Privacy policy and terms text | `_src/legal/*.html` | Word for word from the live site. The build swaps em dashes for plain punctuation. Only change them if Luke asks. |
| Example client sites | `work/<site>/index.html` | Each is one self-contained file (its own CSS and JS inside). Edit directly. |
| Example site screenshots | `assets/work/*.jpg` (+ `thumb/`) | Regenerate with `npm run previews` after changing an example site. |
| Third-party libraries | `assets/js/vendor/` (GSAP 3.12, ScrollTrigger, Lenis 1.1) | Don't edit. Same versions as the live site. |

### Where things live in `_src/build.py`

- Near the top: `GLOSS` (plain-English jargon tips), `BUILD_FROM` and `BUILDS` (the website build price list), `PER_DAY` (care plan price per day), `WORK` (the example sites list).
- `PLANS`, `EVERY_PLAN`, `RECEIPT_ITEMS`: care plans (£29 Essential, £49 Plus, £89 Pro).
- `PEOPLE`, `locmap()` (the Berkshire map), `ticket()` (the referral pass), `GAPCHART`, `FAQ`.
- One function per page: `home()`, `services()`, `pricing()`, `about()`, `work()`, `referrals()`, `contact()`, `legal()`, `notfound()`.
- `head()`, `nav()`, `FOOT`, `cta()`, `phero()`: shared page parts.

Prices appear in one place each. To change a build price, edit `BUILDS`. The estimator ranges in `site.js` (`const ranges = ...`) must match `BUILDS`.

## Commands

Needs Python 3 and Node.js 18 or newer.

```bash
# rebuild the LRWeb pages after editing _src/build.py (Windows: py _src/build.py)
python3 _src/build.py

# one-time setup for the tools (installs Playwright and its Chromium)
cd tools && npm install && npm run setup

# preview locally at http://localhost:8000 (behaves like the live host: /services works, unknown pages show 404.html)
npm run serve

# check before handing anything back: JS errors, broken links, content running off phone screens,
# sideways scrolling, blank screens while scrolling, em dashes
npm run check          # desktop + phone, about 5 minutes
npm run check:full     # adds tablet and small phone, slower

# rebuild example-site screenshots after changing an example site
npm run previews                 # all seven
npm run previews -- tidewater    # just one
```

After any visual change: rebuild, run `npm run check`, and look at the affected sections at desktop and phone sizes. Playwright screenshots are the easiest way to show Luke.

## Things that have broken before (check these when editing)

- **Pinned scroll scenes** (homepage hero and laptop story; Tidewater, VOLT, Northside, Crumb & Kiln and Form & Field sections) use `position: sticky`. They go blank if `overflow` is set on `body` alone. Use `html, body { overflow-x: clip }` together, never `hidden`. `npm run check` looks for blank screens.
- **Don't put a CSS `transition` on a property GSAP animates** (transform, opacity, filter, CSS variables). The two fight and it looks glitchy or stays invisible. This caused the calendar glitch and hidden log rows on phones.
- **Grid and flex children** need `min-width: 0` or long content pushes them off the right edge on phones. So do `<fieldset>`s. This caused the cut-off booking forms.
- **Gradient text** (`background-clip: text`) doesn't work on the odometer counters. Use a solid colour there.
- **The 3D laptop** (`.lap` in `site.css`, timeline in `site.js` under "STORY") is plain CSS 3D. The closed lid sits a hair above the base on purpose (`translateZ(-1.5px)`), or some phones draw the base over it.
- **Page transitions**: clicking an internal link plays the four-colour curtain (green, blue, indigo, navy) from the live site, then navigates. The next page finishes the wipe using a `sessionStorage` flag (`lr-pt`). The example sites do the same from their "Example site" badge.

## Brand

- Colours: green `#3DB88D`, blue `#0B86EA`, indigo `#3F4DE6`, navy `#12018D`, night `#070824`, off-white `#F5F8FA`. The signature gradient runs green to blue to indigo (`--grad` in `site.css`).
- Fonts: Bricolage Grotesque (headings), Instrument Sans (body), IBM Plex Mono (times and small data only). Files are in `assets/fonts/`.
- Logo: `assets/img/logo-light.png` (on dark) and `logo-dark.png` (on light). Favicon: the gradient sun over a horizon.

## Going live

- Pages link to each other as `services.html` etc. The live host should also serve clean URLs (`/services`), as the sitemap uses them. Cloudflare Pages does this automatically.
- The contact form posts JSON to `/api/contact`, the same endpoint the current live site uses. If it fails, the form opens the visitor's email app instead.
- `robots.txt`, `sitemap.xml`, `site.webmanifest` and `404.html` are in place. Update `lastmod` dates in the sitemap when pages change.
- Development happened on the git branch `claude/lrweb-redesign-client-sites-fnplus` in the `colab` repo, inside the `lrweb/` folder.
